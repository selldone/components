# Read-only data sheet

`UDataSheet` presents paginated records and chosen JSON fields in the approved Refined sheet layout. It does not fetch data, change records, or persist customer content.

Pass `items`, `columns`, `loading`, `error`, `search`, `rowOffset`, and native `sortBy`. Each standard column has `key`, translated `title`, optional Material `icon`, initial `width`, `fixed`, `visible: false`, `sortable`, or a display-only `getValue(item)`. Keep a single leading fixed identity column. `extraDataKey` defaults to `data`; `rowKey` defaults to `id`. Optional `storageKey` enables device-local presentation preferences; an empty key disables every storage read/write. The host must derive a separate key from the authenticated user and authorized shop, never record content. Stream uses `selldone:stream-sheet:v1:user:<user-id>:shop:<shop-id>`.

The parent retains authorization, server search, native sort fields, pagination, export, deletion and request errors. The component emits `update:search`, `sort: { key, order }`, and `retry`. Slots `header` and `footer` preserve the surrounding real controls; `cell-{key}` customizes a cell using `{ item, value }`; `actions` retains existing row actions. Cell slots are inside the inspect-value button, so use noninteractive markup or explicitly stop an inline copy value's click. Header/footer wrappers provide 24px desktop and 16px narrow-screen insets.

Columns discovers only keys in the currently loaded successful page. Counts and samples describe that page, not the entire data set. Selection, labels, widths and order remain across page updates; absent selected keys stay visible. With `storageKey`, the same choices also survive reloads on this device for that user/shop. Only versioned column identifiers, exact JSON path segments, visibility, optional custom labels and widths are saved. Never store record values, samples, names, emails, search terms or cell selections. Restored metadata is bounded and validated, keeping the fixed identity and raw-data access visible and appending newly introduced native fields. Unknown/corrupt versions are retained untouched until an actual confirmed layout change. Read/write denial or quota exhaustion shows a neutral localized notice while the current viewer continues working. Scope changes discard pending drags and reset the layout before loading the next scope; dragging saves only on pointer release, and canceled selection/label edits do not save.

Key discovery has bounded depth/key counts and arrays remain whole values. Missing fields, null, empty strings, false and zero remain distinct. JSON keys are exact path segments; dots or slashes inside a key do not imply nesting. No global JSON search/sort or custom-layout export is implied.

The view uses a 48px minimum row, a 40px row index, 55px desktop sticky headings and a fixed identity capped at 180px below 650px. Touch headings grow for their 44px controls. Resizing, fit-to-content, label/order/hide settings, complete-value inspection, successful-copy feedback and contained horizontal scrolling are shared behavior. Fullscreen moves the same component content into a Vuetify fullscreen dialog so selection and the parent's native controls keep their state. When leaving the legacy Smart invert boundary, the fullscreen content and its controls use the native dark theme instead of losing the dark preference or applying a second inversion. Inspector dismissal restores keyboard focus to its trigger or the Columns control when that trigger is gone. No dependency or new API is required.

Run `node --test ui/data-sheet/data-sheet.test.mjs ui/data-sheet/UDataSheet.test.mjs` from the components package for JSON discovery, column selection, server sort intent, copying and focus-return checks. Stream's isolated request/confirmation tests live beside its page. The application integration must also be checked with its existing HMR session at desktop and mobile widths, including loading/error/empty states, actual Smart invert and RTL.
