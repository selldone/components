# Resource metadata

`BResourceMetadata` is the shared merchant-dashboard metadata workspace using the approved Connected composition. Products adopt it first; reuse the same component when adding Metadata to categories, coupons, discount codes and other shop resources.

Pass the currently authorized `shop`, loaded `resource`, the existing API collection segment as `resource-type`, a localized resource name as `resource-label`, current `read-only` permission, and `active`/`parent-busy` state. An optional `resource-icon` slot supplies the resource's identity icon; keep resource-specific copy and icons in the caller. Mount only after the authorized resource is ready, and key the host boundary by shop/resource when appropriate. The component exposes `busy` and emits `saved` with `{ field, value }`; the host applies that exact field to its resource without resetting other form drafts.

The resource identity connects to four section controls: Public, Private, AI Agent and Selldone. The selected header shows the exact column code and one short localized explanation; Selldone uses its canonical logo. Successfully empty sections have their own short title and inert SVG, with a finite sequence of at most four seconds and a complete reduced-motion state. Show Add JSON for writable empty sections and Edit JSON for existing data. Keep file-reference guidance inside the editor and avoid extra empty-state paragraphs or technical Illustration/Animation labels. In the host's edit navigation, Metadata follows Delete with a clear separator.

Each column code has a keyboard/tap-accessible tooltip explaining that it is the field name in the resource's returned data. Writable sections expose brief advanced-use help; the editor also shows the same caution visibly because ordinary setup needs no metadata changes and edits can break custom dashboards or integrations. There is no routine Refresh control; retain failed-read Retry and the existing read/save lifecycle.

Public and Private use the existing authenticated resource-attribute GET/PUT routes; AI Agent uses the same GET route and remains read-only in this merchant UI. For a product, the endpoint is `/api/shops/{shop_id}/products/{product_id}/{field}` with `field` equal to `public_attributes`, `private_attributes` or `ai_agent`. Other callers supply their existing API collection segment. Selldone `meta` is read-only and comes only from the authorized resource projection; never add a system-metadata write endpoint. Public data may reach customers; Private and AI Agent data must remain outside storefront serialization. The server retains the resource's scope, shop-permission and tenant-ownership checks.

Reads distinguish unavailable fields from successfully empty/null values. Drafts remain local, survive section navigation and failed saves, and clear on scope/permission changes. Each save sends only the selected field and checks for changes with a fresh read before the existing full-column PUT. This catches earlier concurrent edits, but the API has no atomic version precondition: simultaneous writes can still race. JSON accepts objects, arrays or null with a 64 KB editor limit. Store file references, never file bytes.

The shared server write boundary strictly validates JSON request bodies as objects containing the selected metadata field, then applies the existing normalized array/null validation and checks JSON encodability before changing the model. Malformed bodies or query parameters cannot substitute for a missing JSON-body field. Existing form-style and internal MCP requests retain their normalized input contract and authorization checks.

The shared English/Persian help, audience captions and empty titles are resource-neutral under `resource_metadata`. Verify with `node @selldone/components-vue/backoffice/resource/metadata/BResourceMetadata.test.mjs` and the product-editor tests. Use synthetic data and request stubs; no production build or live write is required.
