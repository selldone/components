# Storefront route overview

`ShopSiteMap` retains its legacy presentation by default. The domain workspace opts into `<shop-site-map modern :shop="shop" :base-url="actualStorefrontUrl" />` inside its full-screen dialog. `ShopSiteMapModern` owns only the inner content: actual store/root identity, XML sitemap address and copy action, category/page lists, and the existing storefront, product, blog/article, utility and channel route families. Route patterns are informational; this is not a verified inventory of the separately generated XML sitemap. Unpublished pages remain labeled drafts without public links. Titles are plain text, and actual images use the existing shop image/avatar helpers.

Only the existing authenticated `GET_MY_SHOP_CATEGORIES` and `GET_SHOP_PAGES` reads run, with their server-side scope/shop checks unchanged. Category and page states load independently, expose empty/error/retry paths, and request only the first five records of each kind. Each preview is capped at five rows even if an endpoint returns extra items, with the real total and a quiet remaining-item count (for example, 995 more items out of 1000). It does not expand into the complete catalog. A changed shop or closed view rejects late responses. No DNS, domain/OAuth, indexing, publication or content mutations run here. The legacy callers keep their original requests and layout.

The modern inner content is capped at 1040px with 30px/28px desktop insets, 17px widgets with 23px padding, 22px/500/35px page title, 15px/500/24px section headings and readable 14px/13px body/reference text. The two-column collections and route groups stack below 700px. Logical spacing, native secure new-tab links, shared action/status/notice/hover primitives and scoped theme-token styles retain RTL and light/dark behavior. The parent owns full-screen dialog close, scrolling and focus return.

Run the isolated mocked checks with `node --test backoffice/sitemap/ShopSiteMapModern.test.mjs` from the components package. They cover opt-in behavior, bounded preview reads, real remaining counts, errors/retry, late shop/unmount responses, exact routes, safe links, plain titles and SFC/style compilation; they make no application or live API requests.
