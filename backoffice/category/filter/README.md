# Category filters

`BCategoryFilterEditor` is the shared filter configuration form. It uses the same modern presentation in the catalog's fullscreen root/category dialog and the existing category editor's Filter tab, including its Classification and catalog hosts. When configurable data exists, visible filters, technical specifications and generated output occupy separate surface cards with 16px canvas gaps; confirmed empty data uses one compact state. There is no separate legacy renderer or copied form.

## Flow and boundaries

- In the normal form, dimension choices retain their native order, availability and resolved shop-specific names/icons. Price, Discount and Original remain available after filter data loads; Brand and variant choices follow the existing saved/ignored-bucket rules. Material is a variant dimension, not a product type or status.
- Native checkbox roots explicitly auto-place in their two-column grid (one column on phones); Vuetify's default named `control` grid area must not place every choice into the same cell. Each choice retains its full label and at least 44px height.
- Technical specifications use the existing server-key multi-select with multiple selection, removable chips and native clear behavior. It cannot create arbitrary keys; clearing it does not clear other filters.
- Choices are local drafts. Save & regenerate sends the original selected specification strings and ignored dimensions through the existing category filter PUT. The returned filter data replaces the generated values and emits `edit-filters`; the catalog host updates its root/category target and closes the dialog on success. Embedded category-edit forms remain open. Pending or failed saves keep the catalog dialog open; errors retain the draft and use the native notification service.
- Standalone Cancel restores selections from the latest returned filter data and emits `cancel`; it cannot undo an earlier Save. The catalog host closes its dialog. Closing a native host dialog does not submit the form.
- The category editor opts into `embedded`: one inline Save & regenerate action and a scope explanation follow the content; there is no Cancel or viewport footer. Saving updates only filter configuration and emits the same `edit-filters` event without closing the category editor or saving unrelated settings drafts. Standalone callers keep Cancel and host-owned completion behavior.
- Loading, failed reads and confirmed empty data are distinct. Save stays unavailable until the initial GET succeeds. Failed reads keep cached saved output and local selections, display a neutral error with Refresh, and permit no regeneration; retries do not clear the cache or draft before succeeding. Pending reads/saves cannot be duplicated.
- When a successful read finds no saved values, available specification keys, saved specification selections or ignored non-forced variant settings, one compact empty state replaces the three form cards. It contains a brief explanation, a native product/filter illustration and one Save & regenerate action. Standalone empty states keep Cancel inside that same state instead of a separate footer. Null filters, empty objects and empty variant arrays use this compact presentation; existing ignored configuration, specification drafts, selectable specification keys and real generated values keep the normal editable form.
- Partial empty dimensions/specifications still explain how filterable product values become available. Existing selected spec chips remain removable even when the server offers no new specification keys. Empty saved output contains guidance instead of a zero-row Price table. The GET provides filter data and specification keys, not a product count, so empty guidance never claims the category has no products.
- Generated values are read-only saved output. Brand/variant values remain while a choice is changed locally; regeneration removes ignored buckets. Price ranges hide immediately when Price is ignored. Specification headings follow the current selection, while new values require regeneration.
- Disclosures organize the same generated groups into separated, bordered panels without selecting values, regenerating data or changing ignored dimensions. Native neutral read-only chips keep each generated brand, variant and technical value visually distinct, with a compact 24px minimum height, 2px/6px padding and 4px gaps while retaining readable 13px/20px labels. Every group and currency remains reachable on narrow screens and in RTL.
- The fullscreen header states Root filters or Category filters once, followed by the existing loaded shop → ancestor → current-category breadcrumb. Every identity uses a regular 32px avatar, with the shop logo first and native fallbacks when an image is missing. The path is informational while editing; it does not navigate or reset the draft. It reuses the existing hierarchy response (up to three ancestors) without another request.
- The catalog passes `hideContext` to avoid repeating the purpose/location block inside the form. Embedded/category-edit callers keep that block by default, so their heading and scope remain available.

## Preserve native value renderers

- Colors keep their real color marker and `coloName` label.
- Smart Variant Assets keep `UVariantAssetImage`, its raw value, 16px image, canonical shop asset resolution and native image/hover classes. Display names still use `removeVariantAsset()`; image markers must not become visible label text.
- Currency ranges use the native small `UCurrencyIcon` with its flag/symbol and an inline currency code, without the duplicate lower caption or currency-name line. `FormatNumberCurrency` still formats every minimum/maximum. Rows use 3px vertical cell padding; they are read-only values, not an editable range or conversion.
- Narrow price groups put the currency above labeled minimum/maximum values. Long formatted values remain complete without horizontal overflow; logical spacing preserves RTL order.
- Technical values retain their existing three-word presentation. The form does not add a Tags field or replace product-specific asset handling with generic thumbnails.

The existing shop/root/category API paths, token scopes, shop authorization and category-write permission checks remain unchanged. The catalog's vendor guard remains in its host; this presentation does not introduce vendor endpoints or new access.

Shared-editor integration checks use deferred saves to verify pending/error persistence and successful root/category host closure while retaining embedded-editor behavior.

The shared-editor and dialog-header checks pass, alongside the catalog list checks. An isolated native Vuetify preview verified root, category and embedded-editor contexts across desktop, 390px mobile, 320px RTL with large currency values, and native dark/reduced motion. Rendered checks measure all checkbox rectangles for distinct, non-overlapping placement and at least 44px height, plus the actual 16px gaps between section cards; overflow checks alone cannot detect controls sharing a grid cell. It used the actual shared form, native chips/color/asset/currency renderers and synthetic local assets; keyboard containment and native dismissal were checked without application requests. Real filter regeneration and legacy Smart Invert were not exercised.

The exact catalog dialog template and scoped styles were also checked with native breadcrumbs at root, three loaded ancestors plus the current category, and 320px Persian RTL with long names. All images render as single 32px avatars, the purpose heading appears once, separators stay attached to their following crumb, and Close/footer remain reachable without overflow. The existing host has no native activator; Escape dismisses it and focus returns to the document body. This header change preserves that existing dismissal behavior.

The compact generated-value refinement was rechecked on desktop and 320px Persian RTL: 33 chips measure 24px with 13px/20px text, eight currency identities keep their code adjacent without a lower caption, desktop price cells measure at most 29px, and native 16px asset previews and large amounts fit without overflow. Chip sizing uses an explicit border-box so inherited content-box sizing cannot add padding outside the intended height.
